# Создать проект и первую задачу

Используйте, когда пользователь поручил завести новый проект в TELOS SPACE.
Для `telos_key_`-ключа нужны `projects:write`, `projects:read`, `tasks:write` и
`tasks:read`. Прежний токен WRITE также поддерживается. Существующий проект
и участие в нём для создания не требуются.

1. Соберите код (латиница и цифры, 2–10 символов), название и доступные поля
   паспорта. Участников указывайте точными логинами. Владелец определяется
   сервером по текущему пользователю; `owner_id` не передаётся.
2. Покажите пользователю паспорт и первую задачу. Если создание уже явно
   поручено с этими параметрами, выполняйте согласованный объём; иначе
   дождитесь подтверждения.
3. Сгенерируйте отдельный UUID для каждой записи и сохраните его вместе с
   исходными аргументами до получения результата. При потере ответа
   повторяйте тот же UUID и те же аргументы, включая после переподключения.
4. Вызовите `telos_create_project`, затем `telos_get_project(full_text=true)` с
   возвращённым `project_key`. Сверьте полный паспорт.
5. Создайте первую задачу через `telos_create_task`. Без `stage` используется
   первая стадия нового проекта.
6. Верните ключи и `url` из ответов; не собирайте ссылки самостоятельно.

## Пример вызовов

UUID ниже приведены для примера. Для нового создания используйте новые UUID;
для повторов сохраняйте исходные.

```json
{
  "tool": "telos_create_project",
  "arguments": {
    "key": "LAUNCH",
    "name": "Запуск продукта",
    "description_sections": {
      "problem": "Договорённости команды хранятся в разных местах.",
      "goal": "Согласовать и выполнить запуск.",
      "expected_result": "Продукт опубликован, проверка приёмки пройдена.",
      "additional": "## Ограничения\n\nСроки уточняем после оценки команды."
    },
    "stages": [
      {"name": "Подготовка"},
      {"name": "Выполнение", "color": "#58a6ff"},
      {"name": "Принято", "color": "#3fb950", "is_done_stage": true}
    ],
    "request_id": "a324153e-c4a9-4616-98e2-cbd311ba16aa"
  }
}
```

```json
{
  "tool": "telos_get_project",
  "arguments": {"project_key": "LAUNCH", "full_text": true}
}
```

```json
{
  "tool": "telos_create_task",
  "arguments": {
    "project_key": "LAUNCH",
    "title": "Согласовать критерии приёмки запуска",
    "description": "Зафиксировать проверяемый результат и ограничения запуска.",
    "request_id": "184b020d-c1dc-4010-ad05-32fc66226d85"
  }
}
```

`description_sections` имеет приоритет перед `description_md`. Если блоки
не переданы, Markdown сохраняется в исходном виде. По умолчанию статус —
`PLANNING`, цвет — `#58a6ff`, начало — текущая дата, команда включает владельца,
стадии берутся из стандартного набора; начальная свободная доска создаётся
автоматически. Можно передать `member_usernames`, `status`, `color`, `icon`,
`start_date` и `due_date`; правила совпадают с REST `ProjectCreateSchema`.

Занятый код, неизвестный участник, некорректные даты и стадии отклоняются без
частичного создания. Если UUID занят другим запросом, исправлять payload
при том же UUID нельзя: проверьте исходный запрос и используйте новый UUID
для действительно новой операции. Отзыв ключа, scope или доступа закрывает
и чтение прежней квитанции; повтор не обходит текущие права.
