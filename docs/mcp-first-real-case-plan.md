# Первый реальный кейс MCP и состояние доработок

Первый кейс — **6 ноября 2026 года**, исходная проверка — **7 ноября**.
Актуальность сведений сверена **14 ноября 2026 года**.

Это исторический разбор и статус его предложений. Текущие контракты,
инструкции подключения и ограничения описаны в [Арис и MCP](agent.md).
Прежний план совместимости с `tt_`, короткими именами и `ttk_` больше
не действует: после согласованной унификации используются только `telos_`,
`telos_key_`/`telos_token_` и прежний транспортный адрес `/mcp`.

## Результат исходного кейса

Codex через настоящий MCP прочитал проекты и задачи BKS Term (`TERM`),
создал `TERM-2` по Claude Code, уточнил описание и добавил комментарий
о частичной готовности в `TERM-1` по Codex. Сохранение проверялось чтением,
автор комментария определялся сервером.

`get_task` вернул превью длинного описания. Это подтвердило неудобство
дочитывания, но не потерю текста в БД. Дубли основных и прежних имён
затрудняли выбор операции. Внешний доступ использовал HTTP.
Один самописный клиент не смог прочитать SSE-строку длиннее 64 КиБ;
после чтения целого события JSON разбирался. Это ограничение клиента,
а не основание обрезать протокольный каталог.

Исходная локальная проверка 07.11: 1288 backend passed без пропусков,
901 frontend passed, 2 skipped; ещё 10 целевых проверок каталога прошли.
Включены настоящие PostgreSQL и MCP Streamable HTTP с синтетическими ключами;
модели и браузерный API были управляемыми. Эти числа относятся к тому срезу,
последние проверки и продовая версия — в [MEMORY](../MEMORY.md).

## Что изменилось после кейса

| Предложение первого плана | Текущее состояние |
| --- | --- |
| Полное чтение длинного текста | `telos_get_task` и `telos_get_project` принимают `full_text`; метаданные превью содержат способ дочитывания. Есть `telos_get_comment`. |
| Повторы записи без дубликатов | Прямые создания используют UUID `request_id` и общие транзакционные квитанции с повторной проверкой доступа. Для `telos_execute_project_tool` request_id обязателен при записи. |
| Защита параллельного изменения задачи | Возвращается `revision`; `expected_revision` отклоняет устаревшую запись. У чек-листа и итогового отчёта отдельные ревизии. |
| Компактный каталог | Развёрнут единый каталог без алиасов: 45 нативных MCP-инструментов. Дополнительные проектные операции раскрываются адресно через `telos_list_project_tools`. |
| Диагностика схем и обновления клиента | Есть `catalog_probe`, fingerprint исходников и хэш схем, сравнение свежих сессий и ограничения нативной проверки Codex. |
| Расширение предметных сценариев | Создание проекта, документы и другие операции доступны через общие сервисы; точные схемы нужно получать из текущего каталога. |
| HTTPS | Отложен пользователем; переход на домен/TLS не входит в завершённые доработки. |

Реализации развёрнуты на проде. Предыдущее утверждение «изменения только локально»
устарело. После TELOS-10 head Alembic — `e92a74c610bf`; числа 67/69/70
из ранних MCP-проверок не являются текущим размером нативного каталога.

## Как проверять продолжение

- Получать схемы в свежей сессии, сравнивать нормализованный каталог,
  отдельно фиксировать серверную версию и то, что реально видит клиент.
- Сверять полный Unicode/Markdown-текст, а не превью или его суффикс.
- При неизвестном исходе записи повторять тот же UUID и аргументы.
  Проверять конфликт аргументов и отзыв доступа отдельными сценариями.
- Не возвращать удалённые имена и алиасы ради уменьшения объёма метаданных.
- Не выдавать успешную SDK-сессию за полную проверку каталога интерфейса Codex,
  а успешный TCP-connect — за успешный защищённый вызов MCP.
