# Память проекта

Последняя сверка: 10 ноября 2026 года. Здесь текущие факты и границы,
а не журнал разработок. Перед продолжением проверь файлы, Git и Docker.

## Назначение и репозиторий

TELOS SPACE — «Пространство смыслов»: проекты и разовые задачи, ИСР,
свободные доски, календарь/Гантт, документы, риски и командный чат.
Помощник ARIS (Арис) — проектный менеджер, мужской род.
В проекте одна общая вкладка «Чат» с обращением «Арис, …» / «ARIS, …»;
личные диалоги приватны. Прежние обращения не запускают помощника.

Основная ветка — `main`, remote — `origin`:
`https://github.com/BKSLab/telos-space.git`. Репозиторий переименован с
`project-management-dashboard-vera`; локальный каталог оставлен прежним.
Запуск и карта документов — [README.md](README.md), правила — [AGENTS.md](AGENTS.md).
Backend — [FASTAPI_PATTERNS.md](FASTAPI_PATTERNS.md), UI —
[docs/DESIGN_GUIDE.md](docs/DESIGN_GUIDE.md).

## Текущая унификация

По прямому поручению пользователя тестовый проект обновляется целиком:
без прежних имён, алиасов и переходных контрактов. Реализованы и развёрнуты:

- HTTP Ариса: `/api/v1/aris/conversations`, `/aris/requests`, `/aris/pending`;
  проектные приватные диалоги — `/projects/{id}/aris/conversations`.
  Решение действия общего чата — `/projects/{id}/chat/aris/actions/{id}/decision`.
- Личные задачи, внимание HTTP/WS и календарь — `/api/v1/users/me/*`.
  Смена стадии — `PATCH /tasks/{id}/stage-placement`, перенос —
  `POST /tasks/{id}/transfer`, preview — `/transfer/preview`.
  Доски и стикеры адресуются по `board_id`.
- Единые `Aris*`, `AgentConversationsService`, `AgentRoutingService`,
  `Board*`, `BoardSticker*` и `TaskTransfer*`; пустые сервисные обёртки удалены.
  Ошибки AI — `AiProviderError` (503) и `AgentAnswerError` (502).
  Доменные исключения находятся в `exceptions`, не в HTTP и сервисах.
- HTTP operationId уникальны и заданы явно; tags используют kebab-case.
  Каталог справки: **215 API (213 HTTP + 2 WS), 46 MCP, 72 проектных действия**.
  Единственный источник — `python -m src.integration_docs`; `--check`
  сверяет `frontend/src/content/integrations.generated.json`.
- MCP и инструменты Ариса используют только `telos_<действие>_<сущность>`.
  Полный MCP-каталог содержит 46 инструментов. Протокольный endpoint — `/mcp`.
  Scopes вроде `agent:ask` обозначают права и остаются текущим контрактом.
- Ключ с scopes — `telos_key_<8 lower hex>_<32 lower hex>`, READ/WRITE-токен —
  `telos_token_<secret>`. В БД хранятся хеши; публичный `key_prefix` — только
  8 hex, префикс токена — 8 случайных символов после маркера формата.
  Авторизация HTTP/MCP — `Authorization: Bearer`; cookie по умолчанию —
  `telos_session`. Заголовок `X-API-Key` и публичное поле `kind` удалены.
- UI: личный `/chat`, командный `/projects/:key/chat`, приватный проектный
  `/projects/:key/conversations`, знания `/projects/:key/knowledge`.
  Знания не читают приватную переписку. Старые UI redirect-маршруты удалены.
  Профиль и ключи — `/profile?tab=keys`, справка — `/help/api` и `/help/mcp`.
  Storage использует `aris.*` / `telos.*`, ICS UID — `@telos-space`.

Физические SQL-имена таблиц/индексов/FK сохранены: это хранилище данных,
а не API-алиасы. Новая миграция `d86e1a90c427` поверх `b64da02f537c`
меняет только четыре комментария колонок, без изменения структуры и строк.
Повтор действия использует сохранённую квитанцию независимо от её UUID;
новые вызовы имеют нейтральный request ID. История и персональные данные сохранены.
Канонические описания — [docs/agent.md](docs/agent.md),
[docs/PROJECT_CHAT.md](docs/PROJECT_CHAT.md), [docs/knowledge.md](docs/knowledge.md).

## Инварианты

- HTTP, MCP и инструменты Ариса используют общие сервисы и доменные права.
  Локальные членство/владение определяют доступ, авторство задаёт сервер.
  `User` хранит username и части ФИО; корпоративной модели пользователя нет.
- Bearer имеет приоритет над cookie. Неверный Bearer не заменяется рабочей
  cookie-сессией. Управление ключами требует UI-сессии; ключ действует только
  в пределах scopes и текущего доступа владельца.
- WriteGate, отдельные подтверждения опасных действий, UUID-квитанции,
  транзакции и повторная проверка актуального доступа обязательны.
  Pending ничего не изменяет; подтверждение не расширяет права.
  Повтор отправки чата защищён блокировкой и атомарной записью хода/ответа.
- Личная задача не имеет project_id/stage_id/размещения ИСР; её владелец —
  постановщик TaskParticipant с user_id, состояние — status. У проектной
  задачи состояние задаёт стадия, участники связаны через project_member_id.
- `WbsNode` — контейнер. Пул, свободная карточка холста и размещение в разделе —
  разные состояния; `wbs_node_id = NULL` не означает автоматически пул.
  Перенос снимает прежние проектные связи одной транзакцией и сохраняет ID,
  историю, комментарии, чек-лист, вложения и неизменяемые версии отчёта.
- Личные доски принадлежат локальному пользователю. Доски поддерживают фигуры,
  стикеры, соединители, группы, locks, шаблоны, историю и ревизии.
  Цвета стикеров — canonical hex; пользовательские формы/геометрия сохраняются.
- Файлы локальные. Оригинал принадлежит проекту либо задаче; проектный поиск
  включает вложения задач без копирования. Удаление комментария сохраняет
  оригиналы; удаление файла снимает связи. Автор загрузки определяется сервером.
- Парсинг текста/CSV/PDF с текстовым слоем/DOCX/Excel выполняет код проекта.
  `file_processing_jobs` не зависит от RAG. Полный текст и FTS сохраняются
  атомарно; PostgreSQL outbox запускает семантическую индексацию.
  Срок готовности jobs сравнивается с часами БД. Backfill без AI —
  `python -m src.files.backfill --batch-size 200`; `--enqueue-missing`
  отдельно разрешает обработку прежних необработанных оригиналов.
- Миграции добавлять поверх существующей цепочки, base не заменять.
  Существующую БД и данные ради новой схемы не пересоздавать.

## Границы и AI

Не входят корпоративные SSO/SD, staff/company roles, PM-agent/обращения,
iframe/postMessage, external cases, корпоративные storage/OCR,
Phoenix/OpenInference/OTLP и служебные deploy/health-каталоги.
Потоки/flows и учёт времени исключены. Загрузка календаря — число задач.
Сохранены свои PostgreSQL, Redis, Qdrant и настройки LLM/embeddings/vision.
Для диагностики разрешён только текущий ключ этого проекта; чужие ключи
не брать, не копировать и не использовать даже для сравнения.

Последний согласованный текстовый профиль — `openai/gpt-6-luna` через Polza,
`AGENT_PROVIDER=openai`, thinking выключен, reasoning effort none.
`AGENT_MODEL` управляет runtime и structured LlmClient (router/память/WriteIntent),
а не `LLM_MODEL`. Native runtime — PydanticAI 2.59.0 / OpenAI SDK 3.26.0.
Vision — `qwen/qwen3-vl-30b-a3b-instruct`, только для изображений;
OCR сканированных PDF не добавлен. Embeddings — отдельные настройки.
Смена имён и ключей не должна менять модели или запускать переиндексацию.

Сетевые лимиты Ариса — 30 с и две попытки HTTP; общий deadline хода — 600 с.
Повторяется запрос модели, а не ход с уже выполненными инструментами.
Vision — 300 с / 3 попытки, embeddings — 120 с. Polza cache routing использует
уникальный prompt_cache_key на логический вызов; доменных повторов нет.
Сохранённый обзор — датированный результат, не новая генерация: чтение
`telos_get_latest_project_summary` использует общий AnalyticsReportReader.
Ограниченные live-замеры не дают гарантии p95; текущие модели после этого
рефакторинга заново не измерялись.

Бренд, аватар и знак — [docs/logo/TELOS_SPACE_BRAND_CONCEPT.md](docs/logo/TELOS_SPACE_BRAND_CONCEPT.md).
UI использует одну оболочку, тёмную тему и существующие tokens. Мобильные
браузерные проверки с mock API не подтверждают физические Android/iOS,
настоящую экранную клавиатуру и пользовательскую работу с live API.
Service worker и автономные записи не добавлены; HTTPS/PWA-установка отложены.
