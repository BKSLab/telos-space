# Память проекта

Последняя сверка: 3 ноября 2026 года. Это состояние личного проекта;
перед продолжением проверяй текущие файлы, `git status` и состояние Docker.

## Назначение и состояние

TELOS SPACE — личный трекер проектов и разовых задач с ИСР,
свободными досками, календарём/Ганттом, документами, рисками, командным чатом
и проектным менеджером Арисом. Выборочный перенос возможностей рабочего проекта завершён.
Основная ветка — `main`, основной remote — `origin`:
`https://github.com/BKSLab/telos-space.git`. Репозиторий GitHub переименован с
`project-management-dashboard-vera`; его ID, refs и настройки видимости сохранены.
Локальный каталог и имена Docker Compose остаются прежними.

Подключены:

- Проектные и личные доски: фигуры, стикеры, соединители, группы, блокировки,
  шаблоны, история, ревизии, очередь сохранения, SVG/PNG и создание проекта из доски.
- «Мои задачи», личные задачи, переносы между проектами и личным списком,
  неизменяемые версии итоговых отчётов, персональное внимание через HTTP/WS,
  иконки проектов, общий дашборд и аналитика.
- Личный/портфельный календарь, Гантт, зависимости, baseline, критический путь,
  загрузка по количеству задач, PNG/PDF и выпуск/отзыв ICS-подписок.
- PydanticAI 2.59.0 runtime (OpenAI SDK 3.26.0), WriteGate, инструменты проекта/личного контекста/доски,
  квитанции действий, очередь с lease/recovery, прогресс и единое окно «Чаты».
  В проектной вкладке только общий чат с обращением «Арис, …»; `/chat` открывает
  личный диалог и меню прежних приватных проектных диалогов и знаний.
- Компактная личность Ариса, 14 нативных отложенных наборов инструкций/инструментов,
  ленивая загрузка проектного retrieval и WriteGate перед первой записью.
  История и результаты ограничены по объёму; фоновое саммари не задерживает ответ.
- Личные/сервисные `ttk_`-ключи со scopes, аудитом и отзывом; прежние `tt_`
  READ/WRITE-токены и `/mcp` сохранены. Есть опциональный отдельный MCP-процесс.
- В знаниях сохранены ИСР, документы, риски, комментарии, локальные файлы
  и саммари; добавлены итоговые отчёты задач.

## Инварианты, которые важно сохранять

- Проектный доступ задают локальное членство и владение; личные доски принадлежат
  локальному пользователю. Владелец личной задачи — её постановщик через
  `TaskParticipant` с `user_id`; у проектного назначения используется `project_member_id`.
- `User` хранит `username`, фамилию, имя и отчество. Не заменять его корпоративной
  моделью и не ожидать у ORM готового поля `full_name`.
- Bearer имеет приоритет при одновременной передаче с cookie. `ttk_`-ключ не
  позволяет действовать от чужого имени. Управление ключами требует UI-сессии.
- `agent:ask` разрешает читать доступные владельцу данные; изменения требуют
  дополнительных scopes записи. Подтверждение не расширяет исходных прав.
- Пользовательское имя — Арис, проектный менеджер, мужской род. Технические
  `Tim*`, `/tim`, storage keys и старые сообщения не переименованы. Старые
  `/agent` и `/knowledge` перенаправляются в `chat?view=personal` и
  `chat?view=knowledge` с сохранением query/hash; проектный `view=vera` ведёт
  на `/chat`. Проектные личные диалоги
  сохранены отдельно: список `/tim/conversations` не включает их автоматически.
- Личная задача не имеет `project_id`, `stage_id` и размещения ИСР; её состояние
  хранится в `status`. У проектной задачи состояние определяется стадией.
- `WbsNode` — контейнер, не задача. В ИСР есть пул, свободная карточка на холсте
  и размещение в разделе. Нельзя сводить все `wbs_node_id = NULL` к пулу.
- Перенос очищает старые проектные связи и размещение ИСР атомарно, сохраняя
  ID задачи, комментарии, чек-лист, вложения, историю и версии отчёта.
- Индексация использует PostgreSQL outbox. Готовность заданий сравнивается
  с часами БД, чтобы рассинхронизация времени worker не задерживала свежие jobs.
