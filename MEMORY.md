## Проект и репозиторий

TELOS SPACE — «Пространство смыслов»: проекты и разовые задачи, ИСР,
свободные доски, календарь/Гантт, документы, риски и командный чат.
Помощник ARIS (Арис) — проектный менеджер, мужской род. В проекте одна
общая вкладка «Чат» с обращением «Арис, …» / «ARIS, …»; личные диалоги приватны.
Знания проекта не читают приватную переписку.

Основная ветка — `main`, remote `origin` — `https://github.com/BKSLab/telos-space.git`.
Локальный каталог сохранён под прежним именем `project-management-dashboard-vera`.
Запуск и карта документов — [README.md](README.md), правила — [AGENTS.md](AGENTS.md).
Backend — [FASTAPI_PATTERNS.md](FASTAPI_PATTERNS.md), UI — [дизайн-гайд](docs/DESIGN_GUIDE.md).

## Контракты и права

- HTTP, MCP и инструменты Ариса используют общие сервисы и доменные права.
  Автор задаётся сервером; доступ определяется текущим локальным членством/владением.
  `User` хранит username и части ФИО; корпоративной модели пользователя нет.
- Канонические имена инструментов — `telos_<действие>_<сущность>`, без алиасов.
  Каталог: **200 API (198 HTTP + 2 WS), 45 MCP, 70 проектных действий**.
  Источник — `python -m src.integration_docs`; `--check` сверяет generated JSON.
  Физические SQL-имена сохранены, они не являются публичными API-алиасами.
- Авторизация — Bearer (`telos_key_<public_id>_<secret>` или `telos_token_<secret>`),
  cookie сессии — `telos_session`. Bearer имеет приоритет; неверный ключ
  не заменяется cookie. Управление ключами требует UI-сессии.
  Scopes ограничены текущим доступом локального владельца.
- WriteGate, подтверждение опасных действий, UUID-квитанции и повторная проверка
  актуальных прав обязательны. Pending не изменяет данные; повтор проверяет доступ.
  Обновление auth не фиксирует бизнес-транзакцию. Worker хранит ID credentials
  и снимок прав, без секрета и расширения прав после постановки вопроса в очередь.
- Арис: `/api/v1/aris/conversations`, `/aris/requests`, `/aris/pending`;
  приватные проектные диалоги — `/api/v1/projects/{id}/aris/conversations`.
  Решения в общем чате — `/api/v1/projects/{id}/chat/aris/actions/{id}/decision`.
  MCP — `/mcp`; отдельный процесс включается только compose-профилем `mcp`.
- Личные задачи, внимание HTTP/WS и календарь — `/api/v1/users/me/*`.
  Разовая задача не имеет project_id/stage_id/размещения ИСР; владелец —
  постановщик TaskParticipant с user_id, состояние — status. Проектная задача
  использует стадию, её участники связаны через project_member_id.
- `WbsNode` — контейнер. Пул, свободная карточка холста и размещение в разделе —
  разные состояния; `wbs_node_id = NULL` не определяет пул. Перенос задачи одной
  транзакцией снимает прежние проектные связи, сохраняя ID, историю и результаты.
  Доски со стикерами, фигурами, соединителями и группами — отдельная подсистема.

Канонические описания: [Арис/MCP](docs/agent.md), [чат](docs/PROJECT_CHAT.md),
[ИСР](docs/wbs.md), [доски](docs/boards-contract.md), [личные задачи](docs/personal-tasks.md).

## Документы — TELOS-10

На проде работают единый `DocumentCatalogService` и `/api/v1/documents`:
непрозрачные стабильные `document_ref`, владелец (проект/задача), независимые связи,
создание Markdown и загрузка оригинала, каталог с фильтрами и пагинацией.
Физические источники сохранены; загрузки не создают лишних Markdown-копий.
Общие `DocumentList`/`DocumentView` используются в проекте, задаче и комментариях.
Арис открывает справа основной фрагмент, проверенный по цитате, Unicode и SHA-256;
устаревший хэш не переносит подсветку на изменённый текст.
Личные документы доступны в личном режиме и исключены из проектного Qdrant.

Оригиналы локальные, автор определяется сервером. Удаление комментария сохраняет
документы; снятие связи с задачей сохраняет оригинал. Код извлекает текст из
текста/CSV/PDF с текстовым слоем/DOCX/Excel; для изображений используется vision.
`file_processing_jobs` не зависит от RAG. Полный текст и FTS сохраняются атомарно;
PostgreSQL outbox запускает семантическую индексацию сохранённого текста.
Прямые AI-действия не повторяют OCR. Каждая версия имеет фактические квитанции стадий.

Head — `e92a74c610bf` поверх `d86e1a90c427`. Миграция сохраняет оригиналы и тексты,
переносит ссылки чата/исторических действий, сверяет индекс без нового извлечения,
включает подпись Markdown в FTS и защищает откат новых данных. Старые незавершённые
API-вопросы с неизвестной авторизацией требуют повторного запроса.
Backfill без AI — `python -m src.files.backfill --batch-size 200`;
`--enqueue-missing` отдельно разрешает извлечение прежних необработанных оригиналов.
Подробный контракт и восстановление — [docs/knowledge.md](docs/knowledge.md).

В «Моих задачах» фильтр проекта применяется до пагинации вместе с правами пользователя.

Бренд и аватар — [концепция](docs/logo/TELOS_SPACE_BRAND_CONCEPT.md).
Референс следующих доработок дашбордов и исторические снимки — [docs/ref/README.md](docs/ref/README.md).

Service worker и автономные записи не добавлены; HTTPS/PWA-установка отложены.

## AI и границы

Согласованный профиль — `openai/gpt-6-luna` через Polza, `AGENT_PROVIDER=openai`,
thinking выключен, reasoning effort none. Runtime и structured LlmClient
(router/память/WriteIntent) используют `AGENT_MODEL`, а не `LLM_MODEL`.
Native runtime — PydanticAI 2.59.0 / OpenAI SDK 3.26.0.
Vision — `qwen/qwen3-vl-30b-a3b-instruct`, только изображения; OCR сканов PDF не подключён.
Embeddings — `openai/text-embedding-3-large`, 3072 измерения, настройки `EMBEDDING_*`.
На проде чат и vision используют `LLM_API_KEY`, embeddings — `EMBEDDING_API_KEY`;
оба соответствуют ключу Polza `task_tracker_agent` (проверка 14.11.2026).
Контейнер БД получает общий env, но не использует AI-ключи; старый контейнер БД
при замене ключа не пересоздавался. Изменение имён/ключей не меняет модель и индекс.

Сетевые лимиты Ариса — 30 с и две попытки HTTP; deadline хода — 600 с.
Повторяется запрос модели, а не ход с выполненными инструментами.
Vision — 300 с / 3 попытки, embeddings — 120 с; prompt_cache_key уникален на вызов.
Сохранённый обзор читается через AnalyticsReportReader без новой генерации.
Эти лимиты не являются измерением p95 текущих моделей.

Не входят корпоративные SSO/SD, staff/company roles, PM-agent, встраивание,
корпоративные storage/OCR, Phoenix/OpenInference/OTLP, потоки/flows и учёт времени.
Загрузка календаря — число задач. Настройки PostgreSQL/Redis/Qdrant/AI принадлежат TELOS;
для диагностики разрешён только текущий ключ TELOS, ключи других проектов не использовать.

## Локальное подключение MCP

Codex использует `[mcp_servers.telos-space]` и `TELOS_MCP_API_KEY` из User environment.
Windows app-server может сохранять прежнее окружение после закрытия окна.
В локальном `~/.codex/config.toml` настроен `http_headers_helper`:
`~/.codex/scripts/telos-mcp-headers.ps1` читает текущую User-переменную напрямую.
Секрета в конфигурации/скрипте нет; ACL не менялись. После смены ключа нужно
обновить подключение MCP, новая история не обновляет окружение daemon.
Проверено 14.11.2026 в Codex 0.167.0 через `config/mcpServer/reload` и нативные чтения;
это локальная диагностика клиента, без изменения серверного кода.
Инструкция и границы SDK/нативной проверки — [docs/agent.md](docs/agent.md).
