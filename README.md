## О проекте

**TELOS SPACE** — пространство проектной работы для личных проектов и небольших
команд, которое можно развернуть на своём сервере. Здесь вместе живут цель проекта,
документы, решения, задачи, сроки и результаты. Это помогает понимать, зачем
выполняется работа, что уже известно и какой следующий шаг приведёт к цели.

В названии *telos* означает цель и назначение, а *space* — общее пространство для
замысла и его воплощения. Имя проектного помощника **ARIS (Арис)** вдохновлено
Аристотелем. Смысловая цепочка продукта:

> **Цель → знания и контекст → ясная задача → результат.**

Начните с проблемы и ожидаемого результата. Разложите работу в структуре проекта,
обсудите варианты на доске, соберите знания и назначьте задачи. Следите за сроками
и рисками, сохраняйте итоговые отчёты — контекст останется доступным команде и Арису.
Для разовых дел есть личные задачи, доски и календарь без обязательного проекта.

Репозиторий: [BKSLab/telos-space](https://github.com/BKSLab/telos-space).
Концепция, логотипы и образ Ариса — в [описании бренда](docs/logo/TELOS_SPACE_BRAND_CONCEPT.md).

## Возможности

| Область | Что можно делать |
| --- | --- |
| **Проекты и команда** | Зафиксировать проблему, цель и ожидаемый результат, настроить команду и стадии, сохранить историю изменения срока. |
| **Задачи и результаты** | Вести проектные и личные задачи, назначать участников, добавлять чек-листы, файлы и комментарии, публиковать версии итогового отчёта. |
| **Канбан и структура работ** | Перемещать задачи по стадиям и раскладывать проект на разделы ИСР; открывать одну карточку задачи из разных представлений. |
| **Свободные доски** | Обсуждать идеи с помощью стикеров, фигур и соединителей, работать с группами и шаблонами, отменять изменения, выгружать SVG/PNG. |
| **Календарь и Гантт** | Планировать даты, зависимости и вехи, сравнивать график с baseline, видеть критический путь и загрузку по числу задач, экспортировать PNG/PDF и подключать ICS. |
| **Знания проекта** | Хранить документы и файлы, искать по содержимому, использовать знания и историю как контекст для ответов помощника. |
| **Обсуждения** | Общаться в командном чате, отвечать и цитировать сообщения, прикладывать файлы, упоминать людей и ссылаться на объекты проекта. |
| **Пульс и риски** | Видеть показатели и задачи, требующие внимания, сохранять разборы Ариса, вести реестр рисков и планы реагирования. |
| **API и MCP** | Подключать собственные скрипты и AI-клиенты к тем же данным с правами локального пользователя. |

Интерфейс поддерживает телефон и планшет: полное меню, удобные зоны нажатия,
компактные списки, адаптивные диалоги и сенсорные инструменты досок. Стадию задачи,
даты и размещение в структуре можно менять без обязательного перетаскивания.

## Арис

<p>
  <img src="frontend/public/brand/aris-avatar-128.webp" width="88" height="88" alt="ARIS — проектный менеджер TELOS SPACE">
</p>

**Арис — проектный менеджер внутри TELOS SPACE.** Он помогает разобраться в
контексте, сформулировать задачу, подготовить чек-лист и структуру работ,
оценить риски и выбрать следующий шаг. Когда нужны действия, Арис использует
инструменты приложения для чтения и изменения доступных пользователю данных.

В личном диалоге можно обсудить свои задачи и проекты; переписку видит только её
владелец. В общем чате проекта помощник отвечает на обращение **«Арис, …»**, и
ответ остаётся доступным команде. Личные проектные разговоры сохраняются отдельно.

Примеры обращений:

> Арис, какие задачи просрочены и что стоит сделать первым?
>
> Арис, помоги разбить цель проекта на понятные этапы.
>
> Арис, какие риски могут повлиять на срок и что мы можем предпринять?

Помощник работает с текущими правами пользователя. Опасные действия требуют
отдельного подтверждения; результаты операций и история сохраняются.
В интерфейсе рядом доступны отдельные AI-действия: улучшение формулировок,
подготовка чек-листов, структуры и разборов проекта.

## Данные и размещение

Приложение разворачивается самостоятельно: локальные пользователи, регистрация
по приглашению, cookie-сессия и изоляция проектов. Файлы хранятся на вашем сервере;
для LLM, embeddings и распознавания изображений используются настроенные вами
провайдеры и ключи. При вызове внешней модели необходимый контекст передаётся
этому провайдеру. Текстовые модели и vision настраиваются отдельно.

Backend — **FastAPI и PydanticAI**, интерфейс — **React и TypeScript**.
Данные и история хранятся в **PostgreSQL**, координация realtime — в **Redis**,
векторный поиск — в **Qdrant**. Всё приложение можно запустить через Docker Compose.

## Запуск в Docker

Для новой установки:

```powershell
git clone https://github.com/BKSLab/telos-space.git
cd telos-space
Copy-Item backend/.env.example backend/.env
```

Нужен Docker Compose. Настройки находятся в `backend/.env`; пример —
[backend/.env.example](backend/.env.example). Создавайте файл из примера только
при первом запуске, не заменяя существующие настройки и секреты.

Для контейнерного backend:

```dotenv
POSTGRES_HOST=db
POSTGRES_PORT=5432
QDRANT_URL=http://qdrant:6333
```

`POSTGRES_DB` и `POSTGRES_NAME` должны совпадать. Задайте собственные
`POSTGRES_PASSWORD`, `JWT_SECRET` и `REGISTRATION_INVITE_CODE`.
Для AI-функций настройте LLM/embeddings/vision своего провайдера;
`EMBEDDING_DIM` должна совпадать с размерностью выбранной embedding-модели.
Параметры и ограничения перечислены в `.env.example`.

Из корня репозитория:

```powershell
docker compose up -d --build
docker compose ps
```

Приложение: **http://localhost:5173**. Backend применяет `alembic upgrade head`
перед запуском. nginx проксирует API, MCP и WebSocket. PostgreSQL, Redis и Qdrant
поднимаются тем же Compose. Для остановки без удаления данных: `docker compose stop`.
Для запуска уже собранных образов: `docker compose up -d --no-build`.

Данные сохраняются в `data/uploads` и volumes `pg_data`/`qdrant_data`.
Перед обновлением существующей БД сохраните `pg_dump` и копию `data/uploads`.
Миграции продолжают прежнюю цепочку; откат останавливается, если новые данные
невозможно представить в старой схеме. Не пересоздавайте БД ради обновления.

Backend имеет `/health/live` и `/health/ready`; готовность проверяет PostgreSQL.
Healthcheck Compose использует внутренний порт 8000. Этот порт напрямую
на хост не опубликован. Состояние и логи: `docker compose ps` и
`docker compose logs --tail=80 backend`.

## Разработка без контейнеров приложения

Используйте Python 3.12 и Node.js 22. Базы можно оставить в Docker:

```powershell
docker compose stop backend frontend nginx
docker compose up -d db redis qdrant
```

Для локального backend в `backend/.env` нужны `POSTGRES_HOST=localhost`,
`POSTGRES_PORT=5436`, `QDRANT_URL=http://localhost:6333`,
`CHAT_REDIS_URL=redis://localhost:6381/0`. Для тех же файлов, что у Compose,
задайте `UPLOADS_PATH=../data/uploads` и `AVATARS_PATH=../data/uploads/avatars`.
При возврате к контейнерному backend верните контейнерные адреса.

В первом терминале:

```powershell
cd backend
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\venv\Scripts\alembic.exe upgrade head
.\venv\Scripts\hypercorn.exe main:app --bind 127.0.0.1:8000
```

Во втором:

```powershell
cd frontend
npm ci
npm run dev
```

UI — http://localhost:5173, Swagger локального backend — http://127.0.0.1:8000/docs.
Vite обращается к API на порту 8000; production-сборка использует относительный URL.

Перед публикацией задайте `VITE_PUBLIC_URL` в настройках Vite по примеру
[frontend/.env.example](frontend/.env.example), затем выполните `npm run build`.
Для локальной и Docker-сборки значение можно сохранить в
`frontend/.env.production.local` на основе этого примера.
Значение — подтверждённый HTTP(S) origin без пути, query, hash и учётных данных.
Сборка добавит `canonical`/`og:url` и абсолютные адреса `og:image`/`twitter:image`.
По умолчанию параметр пустой: превью использует локальный `/brand/share-cover.png`,
а внешний адрес не подставляется. Настройка не регистрирует и не привязывает
домен; `telos-space.ru` остаётся кандидатом. Для ссылок backend отдельно используется
`APP_PUBLIC_URL`.

### Телефон и главный экран Android

Мобильное меню открывает все разделы, личные задачи, чаты, профиль и выход.
В профиле есть блок «На главный экран»: когда браузер предлагает установку,
кнопка «Установить приложение» вызывает его штатный запрос. Также можно открыть
меню Chrome/Samsung Internet → «Установить приложение» или «Добавить на главный
экран». Используются фирменный знак TELOS SPACE, иконки 192/512 px и maskable;
приложение открывается отдельно от вкладок браузера. Поддерживающие браузеры
показывают ярлыки «Мои задачи», «Чаты и Арис» и «Доски» при долгом нажатии на иконку.

Для полноценной установки на телефоне нужен доступный с телефона **HTTPS-адрес**.
`localhost`/`127.0.0.1` допускаются браузером для разработки на том же устройстве;
HTTP по локальному IP компьютера не заменяет HTTPS. Подробности — в
[требованиях установки PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).
Адрес, сертификат и внешний доступ настраиваются отдельно; `VITE_PUBLIC_URL`
сам по себе HTTPS не включает. Приложение работает с сервером, автономные записи
и кеширование личных ответов API не добавлены.

## Доступ, файлы и помощник

Cookie-сессия используется интерфейсом. Внешние клиенты поддерживают прежние
`tt_` READ/WRITE-токены и `ttk_`-ключи с выбранными scopes. Ключи ограничены
доступом своего локального владельца; секрет показывается только при выпуске,
в БД хранится хеш. Выпуск и отзыв ключей требуют UI-сессии.
Справка и готовая конфигурация MCP доступны на `/mcp`, новые ключи — на `/my-api-keys`.

`agent:ask` разрешает помощнику читать доступные владельцу данные; изменения
требуют дополнительных scopes записи. WriteGate проверяет разрешение на запись,
опасные действия дополнительно подтверждаются. Подтверждения и результаты
повторов сохраняются в БД. Арис работает в общем окне чатов, проектных диалогах
и по обращению в командном чате.

В проекте одна вкладка «Чат»: начните сообщение с «Арис, …», чтобы обратиться
к проектному менеджеру. Личные проектные диалоги и знания доступны через меню
на `/chat`; их переписка не публикуется команде.

Существующий MCP доступен через `/mcp`. Опциональный отдельный процесс:

```powershell
docker compose --profile mcp up -d --build
# Или из backend с локальными адресами зависимостей:
.\venv\Scripts\python.exe -m src.mcp_server.worker
```

Адрес отдельного процесса по умолчанию — http://127.0.0.1:8021/mcp/.
Он использует те же пользователей, данные, сервисы и правила доступа.
`APP_PUBLIC_URL` задаёт внешний адрес для ссылок помощника и ICS-подписок.
Для существующих клиентов сохранены технические `/tim`, `/mcp`, `Tim*`,
`tt_`/`ttk_` и UID событий ICS.

Файлы сохраняются локально. Текст, CSV, PDF с текстовым слоем, DOCX и Excel
разбираются кодом проекта. Изображения обрабатываются настраиваемым
vision API; его можно отключить. OCR сканированных PDF, `.doc` и презентации
не поддерживаются. Содержание файла не выводится из его имени.

## Проверки

Из `backend`:

```powershell
.\venv\Scripts\ruff.exe check src tests scripts
.\venv\Scripts\python.exe -m pytest -q --cov=src --cov-report=term --cov-fail-under=78
```

Интеграционные тесты поднимают настоящий PostgreSQL через testcontainers;
нужен работающий Docker. Пропущенная интеграционная проверка не подтверждает её результат.
Правила выбора тестов: [backend/tests/README.md](backend/tests/README.md).

Из `frontend`:

```powershell
npm run lint
npm test
npm run build
$env:PLAYWRIGHT_CHANNEL='chrome'
npm run test:e2e
```

Playwright запускает отдельный Vite на порту 4179. Можно использовать Chromium,
установленный Playwright, вместо Chrome. Браузерные сценарии используют
управляемый API; реальные SQL, транзакции, миграции и файловые операции проверяются
отдельно. Для AI используются управляемые модели, если явно не запущена live-проверка.

## Архитектура и документация

Backend: FastAPI, SQLAlchemy, Alembic, PostgreSQL, Redis, Qdrant и PydanticAI.
Слои: HTTP/MCP → services → repositories; отдельные storage и API clients.
Фабрики зависимостей и scopes собраны в `backend/src/dependencies`.
Frontend: React, TypeScript, Vite, Tailwind, TanStack Query, Zustand, React Flow и elkjs.
